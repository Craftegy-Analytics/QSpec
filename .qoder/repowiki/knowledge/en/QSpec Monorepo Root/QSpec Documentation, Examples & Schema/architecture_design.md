This module is a purely declarative asset bundle with no executable code. It is organized into four sibling directories that together define and exercise the QSpec resource format:

- `schemas/v1/qspec.json` is the canonical JSON-Schema (draft 2020-12) declaring the top-level `apiVersion`, `kind`, `metadata`, and `spec` shape, including `parameters`, `query`, `dataset`, `transforms`, and `presentation` sub-schemas.
- `examples/` contains numbered `.qspec.json` manifests (01–11) that each demonstrate one feature — from a minimal dataset to parameterized queries, individual transforms (`filter`, `select`, `rename`, `derive`, `sort`, `limit`), and chart presentations (`line` grouped series, `pie`). `examples/qspec.config.js` registers the `sql()`, `transforms()`, and `charts()` plugins so every manifest can be validated in plugin-aware mode via `qspec validate --config examples/qspec.config.js examples/*.qspec.json`, which runs them against a stub data source without executing real queries.
- `fixtures/valid/` and `fixtures/invalid/` hold hand-crafted manifests used as positive/negative test inputs for schema and rule validation.
- `docs/` holds human-readable specification prose: top-level guides (`introduction.md`, `quick-start.md`, `cli.md`, `data-sources.md`, `datasets.md`, `queries.md`, `parameters.md`, `transforms.md`, `presentations.md`, `plugins.md`, `plugin-authoring.md`, `public-api.md`, `security.md`, `manifest-specification.md`, `specification-versioning.md`, `known-gaps.md`) plus `superpowers/plans/` and `superpowers/specs/` design documents for future extensions.
  The dependency direction is one-way: examples and fixtures depend on the schema and on the CLI's plugin surface; docs describe both. There are no runtime imports between these assets.
